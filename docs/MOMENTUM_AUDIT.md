# Rigid-body momentum and coupling timing

## Audit definition

For each vertical step, infer the unaccounted contact impulse from

`J_inferred = mass * (vz_after - vz_before) - (F_actuator - mass * gravity) * dt`.

Compare it both with the same-step MPM collider impulse and with the previous step's
impulse. This fixture starts at zero velocity and uses gravity 9.81 m/s². Any floor
contact, joint constraint, or other unrecorded force would also appear in the residual.
The audit is therefore a rigid-body bookkeeping test, not a complete soil/body
momentum-conservation proof.

```sh
python scripts/audit_momentum.py docs/evidence/fixed-control/fixed-control-5ms.json docs/evidence/fixed-control/fixed-control-2p5ms.json docs/evidence/fixed-control/fixed-control-1p25ms.json
```

## Finding: one-step feedback delay

| Physics step | Largest same-step residual (N s) | Largest lag-aligned residual (N s) |
|---|---:|---:|
| 5 ms | 0.252294 | 1.4412e-7 |
| 2.5 ms | 0.265924 | 1.4046e-7 |
| 1.25 ms | 0.264916 | 1.3461e-7 |

The full-run signed residual is small even without alignment because delayed
impulses cancel in the total after contact ends. That does not establish correct
same-step timing. A synthetic regression test deliberately covers this trap.

The result agrees with the installed Newton 1.6.0 implementation:

- `SolverCoupledProxy._step_proxy` adds the stored feedback to the rigid input force
  and steps the rigid solver before the MPM solver.
- It then solves the MPM interaction and harvests updated feedback.
- `SolverImplicitMPM.coupling_harvest_proxy_wrenches` divides the collider impulses
  by the timestep to obtain feedback forces.
- With one proxy iteration, the newly harvested feedback is available to the next
  outer step. Additional proxy iterations repeat the solve over the same interval.

This explains the observed timing. It does not establish that the delay is the only
source of the unresolved timestep sensitivity.

## Two explicitly different recorded quantities

New fixture records preserve both:

- `soil_impulse_n_s`: contact impulse generated by the latest MPM solve.
- `applied_contact_impulse_z_n_s`: vertical force from the rigid solver's input
  state, minus actuator force, integrated over the timestep. This is measured from
  the actual input rather than inferred by shifting the MPM trace.

The second channel is specific to this one-body fixture with only actuator and
proxy forces in its input force buffer. The initial rigid velocity is zero. Adding
other external loads requires expanding the accounting.

These channels must remain distinct in the eventual sensor and diagnostic API.
An ideal sensor must declare which quantity it exposes and at which interval it
becomes available. Renaming generated impulse as a same-step applied force would
misrepresent the backend's timing.

## Controlled follow-up

Repeat the same 1.2-second driven motion at a 5 ms physics and controller period,
using one and two coupling iterations. Preserve four rigid substeps and every
material/geometry setting. Audit measured rigid input force in both cases. This is
a coupling-iteration sensitivity check, not a numerical or physical validation pass.
